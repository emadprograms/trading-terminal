# Plan: 02.1-01 - Sync Coordinator implementation

## Goal
Implement a `SyncCoordinator` and update `wsManager` to support buffering, ensuring no data is lost during the "Handover" from REST to WebSocket.

## Context
Currently, `useChartData` subscribes to WS and fetches REST history in parallel. If REST returns data up to 8:00 AM and the WS connects at 8:05 AM, the 5-minute gap is missing. Furthermore, WS ticks arriving *before* REST history is processed might be discarded or cause out-of-order errors in `lightweight-charts`.

## Implementation Details

### 1. WS Manager Enhancements (`src/lib/ws-manager.ts`)
- **Buffer Mode**: Add a flag to `wsManager` to enable/disable buffering for a specific EPIC.
- **Tick Queue**: Store incoming ticks for buffered EPICs in a `Map<string, Tick[]>`.
- **Drain Method**: Add a `getAndClearBuffer(epic)` method to retrieve buffered ticks.

### 2. Sync Coordinator (`src/lib/sync-coordinator.ts`)
Create a new service to manage the "Handover" state machine for a ticker:
- **State: `BUFFERING`**: WS is subscribed, ticks are being queued.
- **State: `FETCHING_HISTORY`**: Initial REST fetch is in progress.
- **State: `BRIDGING`**: Calculating gap between `T_REST_END` and `T_WS_FIRST`. If gap exists, perform a targeted `fetchCandles` for that range.
- **State: `RECONCILING`**: Merging History + Bridge + Buffer.
- **State: `LIVE`**: Ticks flow directly to the store/chart.

### 3. Store Update (`src/store/usePriceStore.ts`)
- Ensure `updatePrice` in the store can be called in bulk (for draining the buffer) without triggering excessive re-renders if possible, or ensure the chart handles the rapid succession of updates.

## Verification Plan

### Automated Tests (`tests/unit/sync-coordinator.test.ts`)
- **Gap Detection**: Mock REST and WS timestamps and verify that the coordinator correctly identifies if a "Bridge Fetch" is needed.
- **Buffer Integrity**: Verify that ticks received during `FETCHING_HISTORY` are correctly preserved and returned during `RECONCILING`.

### Manual Validation
- Observe logs for `[SyncCoordinator] Briding gap of X minutes`.
- Verify the chart shows no "jump" or missing candles between the historical load and the live tick line.
