# Summary: Phase 2.1 - Market Data Synchronization

## Goal
Eliminate the "Data Gap" between historical REST data and live WebSocket streams, ensuring a seamless, continuous chart.

## Completed Tasks
- [x] **WS Buffering**: Added `setBuffering` and `getAndClearBuffer` to `wsManager`. Ticks are now held during initial load to prevent out-of-order errors.
- [x] **Sync Coordinator**: Created `SyncCoordinator` to manage the state machine for ticker synchronization, including gap detection and bridge fetching.
- [x] **Hook Refactor**: Updated `useChartData` to use the coordinator for all initial ticker loads.
- [x] **Verification**: Added unit tests to verify gap detection and bridging logic.

## Key Learnings
- The Capital.com REST API can have up to 15-30 minutes of lag, and session boundaries (like market open) can create larger gaps if the WebSocket starts exactly at open but the REST data hasn't refreshed yet.
- Buffering is critical not just for gap filling, but for preventing `lightweight-charts` from throwing assertions when a live tick arrives *before* the historical data is rendered.

## Remaining Work
- None. Phase 2.1 is complete.
