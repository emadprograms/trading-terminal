# Plan: 02-00 - Market Data API Client & Types

## Goal
Establish the type-safe foundation and REST client for fetching market data from Capital.com, ensuring seamless environment switching between Demo and Live.

## Context
Phase 2 requires integrating real-time and historical data. Before implementing the data flow, we must define the contracts and a client that leverages the existing `useSessionStore` for authentication and proxying.

## Implementation Details

### 1. Type Definitions (`src/types/index.ts`)
Define the exact shapes of the Capital.com API responses to ensure type safety across the application.
- `CapitalCandle`: Interface matching the `/api/v1/prices/{epic}` response (including `snapshotTime`, `openPrice`, `closePrice`, `highPrice`, `lowPrice` as `{ bid, ask }` objects).
- `CapitalTick`: Interface matching the `marketData.update` WebSocket payload (`epic`, `bid`, `ask`, `timestamp`).
- `MarketResolution`: Enum/Type mapping internal timeframes to API resolutions (`MINUTE`, `MINUTE_5`, `HOUR`, etc.).

### 2. Resolution Mapper (`src/lib/api-utils.ts`)
Create a utility to map application-level `Timeframe` (e.g., '1min', '1H') to Capital.com `resolution` strings.

### 3. Market Data Client (`src/api/market.ts`)
Implement a specialized client for market data.
- Use the existing `api` instance from `src/api/client.ts` to benefit from the proxy and token injection logic.
- `fetchCandles(epic: string, resolution: Timeframe, options: FetchOptions)`:
    - Construct the URL: `/api/v1/prices/${epic}`.
    - Apply query parameters: `resolution`, `max`, `from`, `to`.
    - Return a typed `CapitalCandle[]`.
