# Phase 06 Plan 2: Frontend Sync Logic & Startup

## Goal
Implement the two-way manual sync logic in the watchlist store, ensuring the local watchlist matches the Capital.com source of truth on startup, with robust error handling and tracking of local mutations.

## must_haves
- [ ] D-01: Two-way manual sync is implemented in `syncWithRemote` to pull latest from Capital.com and push local changes.
- [ ] D-02: Terminal attempts to override local state with Capital.com's watchlist state exactly on startup.
- [ ] Fallback exists for `initializeWatchlist` if startup fetch fails.
- [ ] `syncWithRemote` operates atomically: only updates local store if push to Capital.com succeeds.
- [ ] `useWatchlistStore` tracks local deletions and additions to resolve sync appropriately.

## Artifacts this phase produces
- Function: `useWatchlistStore.syncWithRemote`
- Function: `useWatchlistStore.initializeWatchlist`
- Field: `pendingAdditions` in `useWatchlistStore`
- Field: `pendingDeletions` in `useWatchlistStore`
- Field: `isInitialized` in `useWatchlistStore`
