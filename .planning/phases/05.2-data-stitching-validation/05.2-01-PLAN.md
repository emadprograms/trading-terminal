# Phase 05.2 Plan 01: Data Stitching & Market Engine Validation

Provide a rigorous E2E test suite to validate the Market Data Engine built in Phase 2. This ensures that historical REST data and live WebSocket streams stitch together seamlessly, and that connection resilience handles network drops without data gaps or memory leaks.

## Requirements
- TEST-05: Test suite must validate seamless data stitching, WebSocket auto-reconnects, environment switching, and prevent subscription leaks.

## Tasks

<task>
  <id>1</id>
  <title>Test Seamless Data Stitching & Recovery</title>
  <read_first>src/lib/ws-manager.ts, playwright.config.ts</read_first>
  <action>Create `tests/e2e/market-data-stitching.spec.ts`. Configure tests to run serially (`test.describe.configure({ mode: 'serial' })`) to avoid Capital.com rate limits. Use Playwright network interception (`page.route()`) to intentionally delay the REST payload to deterministically induce a gap > 1s against the live endpoint. Assert that a `DataStitchingError` is thrown by tracking console errors (`page.on('console', msg => ...)`). Finally, verify that the application correctly recovers by issuing a fresh REST request to backfill the missing candles.</action>
  <acceptance_criteria>
    - Playwright network interception successfully simulates a >1s delay for REST response.
    - `console.error` logs `DataStitchingError` during the intentional gap.
    - System automatically recovers by issuing a new REST request for backfill data.
  </acceptance_criteria>
</task>

  <acceptance_criteria>
    - Test successfully simulates client-side WS disconnect using Playwright `routeWebSocket`.
    - Test successfully simulates server-side disconnect via failure headers to Vercel Proxy.
    - Backoff and reconnect logic triggers for both scenarios.
    - Chart data successfully backfills missing historical candles from the disconnected period.
  </acceptance_criteria>
</task>

## Verification
- Run `npx playwright test tests/e2e/market-data-stitching.spec.ts tests/e2e/market-data-resilience.spec.ts`

- Both explicit delays and explicit failures must trigger the expected recovery behavior.

- Tests MUST run serially to avoid rate-limiting.
- `DataStitchingError` MUST be deterministically triggered using network interception.
- Subscription leak tests MUST use non-watchlist symbols.
