# Phase 05.2: data-stitching-validation - Context

**Gathered:** 2026-06-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Provide a rigorous E2E test suite to validate the Market Data Engine, ensuring historical REST data and live WebSocket streams stitch seamlessly without gaps or memory leaks.

</domain>

<decisions>
## Implementation Decisions

### Time Synchronization Tolerance
- **D-01:** Lenient gap. Allow small delays between the last REST candle and the first WebSocket tick, but fail the test if the gap exceeds a specific threshold (e.g. >1s).

### Reconnection Resilience Simulation
- **D-02:** Test both client-side drops (using Playwright network interception) and server-side disconnects (via failure headers to the Vercel Proxy as introduced in Phase 5.1).

### Subscription Leak Tracking
- **D-03:** Verify leak prevention by switching between assets that are NOT in the watchlist. Due to reference counting (`activeEpics`), watchlist symbols correctly stay subscribed even if a chart is closed. Test with non-watchlist symbols and assert that the `unsubscribe` payload is sent.

### Environment Switching State Clearance
- **D-04:** Verify the old data stays visible until it is smoothly overwritten by the new Live data when switching from Demo to Live.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `playwright.config.ts` / E2E config: Setup targeting the real Vercel environment with mock-bypass and error injection headers.
- `src/lib/ws-manager.ts`: Manages WebSocket connections and reference counts active subscriptions (`activeEpics` Map).

### Established Patterns
- **Live E2E Testing:** Executing tests against the live Vercel URL with proxy handling.
- **Reference Counting Subscriptions:** Symbols added to the watchlist are actively subscribed and will persist even if charts are closed. Leak testing must account for this by selecting non-watchlist symbols.

### Integration Points
- **Vercel Serverless Functions:** Use proxy test headers for server-side disconnects.
- **Sync Coordinator:** Handles the merge between REST gaps and WebSocket ticks.
