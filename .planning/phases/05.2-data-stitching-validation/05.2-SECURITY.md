# Security Audit: Phase 05.2 - Data Stitching & Market Engine Validation

## Threat Model (Retroactive STRIDE)

| Threat ID | Category | Description | Disposition | Mitigation Plan |
|-----------|----------|-------------|-------------|-----------------|
| T-001 | Information Disclosure | Capital.com API keys and user credentials hardcoded in test files. | mitigate | Load all credentials from environment variables (`process.env`) instead of hardcoding. |
| T-002 | Information Disclosure | Man-in-the-Middle (MITM) attacks stealing injected credentials because TLS certificate errors are ignored during proxy fetch. | mitigate | Enforce strict TLS certificate validation (`ignoreHTTPSErrors: false` or omit) when fetching Capital.com API. |
| T-003 | Spoofing | Unrestricted proxying allows attackers to bounce requests through the proxy if accessible externally. | accept | This is an E2E test utility running locally/in CI, not a production API proxy. |

## Accepted Risks
- **T-003**: Accepted as this is an E2E test utility running locally or in CI environments, and the proxy is not exposed in production builds.

## Verification Results

| Threat ID | Status | Evidence/Notes |
|-----------|--------|----------------|
| T-001 | CLOSED | Verified `process.env.CAPITAL_USER`, `process.env.CAPITAL_PASSWORD`, and `process.env.CAPITAL_API_KEY` are used in `tests/e2e/api-proxy.ts` and `tests/e2e/market-data-stitching.spec.ts`. |
| T-002 | CLOSED | `ignoreHTTPSErrors: true` was removed from `tests/e2e/api-proxy.ts` to enforce strict TLS certificate validation. |
| T-003 | CLOSED | Found in Accepted Risks log. |
