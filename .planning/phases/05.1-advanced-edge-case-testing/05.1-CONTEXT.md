# Phase 5.1: advanced-edge-case-testing - Context

**Gathered:** 2026-06-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Expand the E2E test suite to cover complex trading edge cases and error recovery mechanisms, ensuring that attached SL/TP orders cancel properly, half-flatten logic correctly closes bad legs first, and API failures do not permanently lock execution state.
</domain>

<decisions>
## Implementation Decisions

### API Failure Simulation
- **D-01:** Build error injection into the Vercel proxy (triggered via header) rather than using network-level mocks in Playwright.

### Half-Flatten Verification
- **D-02:** Assert against the exact payload sent to the Capital.com proxy to ensure the correct position ID is targeted (the bad leg), rather than relying strictly on UI state assertions.

### SL/TP Ghost Tolerance
- **D-03:** Enforce strict immediate absence. The test must fail if a ghost order appears in the UI at all, even for a fraction of a second.

</decisions>

### Reusable Assets

### Established Patterns
- **Live E2E Testing:** Recent decisions strongly favor executing tests against the live Vercel URL with proxy handling the Capital.com integrations, rather than over-mocking tests locally. 

### Integration Points
- **Vercel Serverless Functions:** The test suites need to inject headers into requests sent via the proxy to trigger specific error states or timeout conditions during test execution.
