# Plan Review: Phase 01.2 Secure Proxy Gateway (Plan 01)

## Summary
The plan is a highly targeted and technically sound approach to resolving the critical ALPN negotiation and CORS blockers. By moving secret injection to Vercel and forcing HTTP/1.1 via `undici`, it directly addresses the "Catch-22" of the current architecture. The transition to granular handlers (`session`, `market`, `order`) is a professional architectural choice that improves maintainability and avoids a monolithic proxy bottleneck.

## Strengths
- **Surgical Technical Fix**: Specifically targets `ERR_ALPN_NEGOTIATION_FAILED` by utilizing `undici` with `allowH2: false`, showing a deep understanding of the underlying network failure.
- **Enhanced Security Posture**: Successfully removes sensitive Cloudflare Access tokens from the client-side bundle, mitigating information disclosure risks.
- **Granular Architecture**: Breaking the proxy into specific handlers allows for better logging, independent scaling, and clearer routing definitions in `vercel.json`.
- **Verification-Driven**: The inclusion of `api/VALIDATION.md` ensures that the "definition of done" is documented and testable rather than assumed.

## Concerns
- **Environment Toggle Logic (MEDIUM)**: Requirement **AUTH-03** (Demo vs. Live toggle) is listed in the requirements but is not explicitly mapped to a task in the implementation.H. It is unclear if the proxy will handle this via a header, a path parameter, or if the frontend is expected to pass a specific flag that the proxy must then map to different upstream credentials.
- **Upstream Error Propagation (LOW)**: Task 3 focuses on successful forwarding. There is no explicit mention of how upstream 4xx/5xx errors from `proxy.trading-terminal.dev` are handled. Without explicit error mapping, Vercel might return generic 500s instead of the actual API error messages needed for frontend debugging.
- **Request Body Handling (LOW)**: While "body forwarding" is mentioned, serverless functions have strict memory and timeout limits. For the `order` handler, ensuring the use of streaming (where applicable) is key to preventing payload-related crashes.

## Suggestions
- **Clarify AUTH-03**: Add a sub-task to Task 3 specifying how the "Demo/Live" environment toggle is propagated through the proxy to the upstream server.
- **Error Mapping**: Add a requirement to the handlers to transparently pass through the status code and response body of the upstream server to ensure the frontend receives accurate API error messages.
