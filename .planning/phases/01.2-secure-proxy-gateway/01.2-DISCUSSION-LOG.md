# Discussion Log: Phase 1.2 - Secure Proxy Gateway

## Participants
- User (Visionary)
- Claude (Builder)

## Discussion Points

### 1. Proxy Architecture & Performance
- **Question**: Should the proxy be a single catch-all or granular file-based?
- **Decision**: **Option B (Granular)**. Separate handlers for `/session`, `/market`, and `/order` to ensure better debugging and maintenance in the long run.
- **Notes**: Performance is a priority. `undici` will be used to minimize latency and force HTTP/1.1 to resolve the ALPN errors encountered with Cloudflare Tunnels.

### 2. Secret Management
- **Decision**: Tiered ownership. Vercel holds Infrastructure secrets (`CF-Access`). GitHub Actions holds Trading secrets (`Capital.com`).
- **Rationale**: Keeps the frontend layer secure while maintaining the backend as the authority for execution.

### 3. Local Development vs. Deployment
- **Decision**: Abandon local development proxy work. Focus on a Vercel-first workflow to ensure the ALPN/CORS issues are solved by architecture in the production environment.
- **Action**: Remove infrastructure-specific header injection from the frontend and `vite.config.ts`.

## Deferred Ideas
- Moving Capital.com credentials to Vercel (Rejected to maintain security separation).
