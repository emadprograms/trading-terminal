# Phase 01.2-01 Implementation Summary: Secure Proxy Gateway

## Objective
Resolved the CORS 'Catch-22' and ALPN negotiation failures by implementing a granular serverless proxy gateway on Vercel. This gateway moves Cloudflare Access token injection server-side, forcing HTTP/1.1 to satisfy Cloudflare Tunnel requirements.

## Key Accomplishments

### 1. Granular Serverless Handlers
- Created `api/_utils.ts` as a shared foundation, utilizing `undici` to force HTTP/1.1 (`allowH2: false`).
- Implemented `/api/session`, `/api/market`, and `/api/order` as standalone Vercel functions.
- Centralized Cloudflare Access Service Token injection in the serverless tier, removing them from the browser.

### 2. Header & Body Handling
- Ensured transparent propagation of `CST`, `X-SECURITY-TOKEN`, and `x-env` headers.
- Implemented bit-for-bit body streaming for POST/PUT requests (essential for order execution).
- Added robust CORS preflight (OPTIONS) handling with appropriate `Access-Control-*` headers.

### 3. Frontend Alignment
- Refactored `src/api/client.ts` to use relative `/api` paths exclusively.
- Simplified client-side logic by delegating infrastructure concerns to the proxy gateway.
- Cleaned up `vite.config.ts` by removing legacy local proxy configurations.

### 4. Verification & Testing
- Developed a comprehensive behavioral test suite in `api/proxy.test.ts` using `vitest` and `undici` mocking.
- Verified that headers are injected correctly and environments (LIVE/DEMO) are selected based on the `x-env` header.
- Fixed `src/api/client.test.ts` to work in Node.js/Vitest environments by correctly extending the Ky client with absolute URLs during testing.
