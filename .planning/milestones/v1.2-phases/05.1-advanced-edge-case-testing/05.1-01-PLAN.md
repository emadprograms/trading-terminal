# Phase 05.1 Plan 01: Advanced Edge Case Testing

## Goal
Expand the E2E test suite built in Phase 5 to cover complex trading edge cases, including attached order cancellations, complex position trimming (half-flatten), and API error recovery. Implement proxy error injection to support these tests.

## Requirements
- TEST-04: Test suite must cover edge cases for attached SL/TP pseudo-orders, `flattenHalfSymbol` leg assassination, and `executingOperations` lock recovery on API failures.

## Tasks

<task>
  <id>1</id>
  <title>Implement Error Injection in Proxy</title>
  <read_first>api/_utils.ts</read_first>
  <action>Update `api/_utils.ts` to intercept requests and check for an `x-inject-error` header. If the header is present, bypass the downstream request to Capital.com and immediately return the mocked HTTP status code specified in the header.</action>
  <acceptance_criteria>
    - The proxy reads the `x-inject-error` header.
    - If present, the proxy returns the specified error code without forwarding the request.
    - Normal requests without the header are unaffected.
  </acceptance_criteria>
</task>

<task>
  <id>2</id>

  <read_first>tests/e2e/advanced-edge-cases.spec.ts</read_first>
  <action>Create `tests/e2e/advanced-edge-cases.spec.ts`. Implement tests that place a market order, attach a Stop Loss and Take Profit, and then cancel the attached SL/TP. Verify that the cancellation calls `updatePositionStopLoss(dealId, 0)` or `updatePositionTakeProfit(dealId, 0)` rather than attempting to cancel a standalone working order.   <acceptance_criteria>
    - Test successfully attaches SL and TP to an open position.
    - Test successfully cancels the attached SL/TP.
    - Test verifies exactly one valid API request per action.
    - Test uses `toHaveCount(0)` to ensure strict immediate absence of ghost positions, failing on any UI flicker.
  </acceptance_criteria>
</task>

<task>
  <id>3</id>
  <title>Test Half-Flatten (Alt) Logic</title>
  <read_first>tests/e2e/advanced-edge-cases.spec.ts</read_first>
  <action>Implement a test that opens 3 separate positions for the same epic at different entry prices (Note: this is an intentional expansion from the 2 positions suggested in the research phase to force partial closure). To prevent test flakiness due to stagnant market prices, the test must explicitly mock the position data response to enforce different entry prices, or gracefully handle cases where entry prices are identical. Trigger the `flattenHalfSymbol` action (Double Alt key). Verify that the system correctly identifies and completely closes the worst legs first, and if necessary, places a counter-order to trim the best leg without cross-netting. Explicitly listen for the `DELETE /api/v1/positions/{dealId}` request and assert that the `dealId` targeted by the system strictly matches the ID of the worst leg determined from the position state. Assert the final net position size is exactly half of the initial size.</action>
  <acceptance_criteria>
    - Test opens multiple positions, explicitly mocking varying entry prices or properly handling identical entry prices.
    - Triggers half-flatten action.
    - The test intercepts the `DELETE` position request and asserts the `dealId` matches the mathematically worst leg.
    - Verifies final net size is mathematically correct.
  </acceptance_criteria>
</task>

    - `executingOperations` lock is verified to be clear after failure.
  </acceptance_criteria>
</task>
