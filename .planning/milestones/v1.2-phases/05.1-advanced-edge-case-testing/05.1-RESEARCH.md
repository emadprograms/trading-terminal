# Phase 5.1: Advanced Edge Case Testing - Research

## 1. Goal Overview
To plan the expansion of the E2E test suite correctly, we must integrate error injection into the Vercel proxy, track precise API payload targets for position closure, and strictly assert UI absence for canceled SL/TP pseudo-orders.

## 2. API Failure Injection (Criterion 3)
**Requirement**: "API failures do not permanently lock the execution state."
**Decision D-01**: Build error injection into the Vercel proxy (triggered via header).

**Implementation Insights**:
- **Proxy Modification**: The Vercel proxy (`api/_utils.ts`) handles all requests via `proxyRequest`. We must update it to read a custom header (e.g., `req.headers['x-inject-error']`). If present, bypass the `undici` request and return the specified HTTP status code (e.g., `500`).
- **State Resilience**: The `useTradeStore` uses an `executingOperations` Set to lock duplicate operations. The lock is managed using `try/finally` and `.delete()`.
- **E2E Strategy**: In a Playwright test, use `page.route` to intercept the outgoing request to the proxy, append the `x-inject-error: 500` header, and proceed. Then assert that the UI properly catches the error (e.g., shows a toast) and the execution lock clears, leaving the Buy/Sell button enabled for retry.

## 3. Half-Flatten Bad Legs First (Criterion 2)
**Requirement**: "Half-flatten logic correctly closes bad legs first."
**Decision D-02**: Assert against the exact payload sent to the Capital.com proxy.

**Implementation Insights**:
- **Core Logic**: `flattenHalfSymbol` in `useTradeStore.ts` calculates net size, sorts positions by `entryPrice` (worst entry first: highest for BUY, lowest for SELL), and closes the bad legs completely to prevent cross-netting.
- **E2E Strategy**: 
  - To test this against the live API, we place two distinct market orders in the E2E test.
  - Intercept the `GET /api/v1/positions` response to read the live `dealId` and `entryPrice` for both legs.
  - Determine programmatically which `dealId` represents the worst leg based on the `entryPrice`.
  - Listen for the `DELETE` request sent to `/api/v1/positions/{dealId}` when half-flatten is triggered via Double Alt or UI.
  - Assert that the `dealId` in the URL strictly matches the `dealId` of the worst leg.

## 4. SL/TP Ghost Tolerance (Criterion 1)
**Requirement**: "Attached SL/TP orders can be cancelled without ghosting."
**Decision D-03**: Enforce strict immediate absence.

**Implementation Insights**:
- **Core Logic**: `cancelWorkingOrder` handles SL/TP pseudo-orders by checking if the ID ends with `_SL` or `_TP`, then calling `updatePositionStopLoss(dealId, 0)` or `updatePositionTakeProfit(dealId, 0)`.
- **E2E Strategy**:
  - Open a position with a strict Stop Loss or Take Profit.
  - In the UI, locate the SL/TP row and click the Cancel button.
  - Playwright enables strict assertions without retries using `expect(locator).toHaveCount(0)`. We should assert that the specific order row locator evaluates to a count of 0 immediately after the API returns the success response. This will ensure the test fails if a state synchronization glitch causes the item to flicker or re-render temporarily.
