# Phase 06 Plan 1: API Proxy & Services

## Goal
Implement the backend Vercel proxy handlers and frontend service methods for Capital.com Watchlist synchronization, including proper error propagation and concrete endpoint mapping.

## must_haves
- [ ] A proxy handler `api/watchlist.ts` is available to route requests to Capital.com.
- [ ] A frontend service `watchlistApi` is available to perform fetch and update operations.
- [ ] Proxy specific errors propagate back to the frontend service clearly.

## Artifacts this phase produces
- New File: `api/watchlist.ts`
- New File: `src/services/watchlist.ts`
- Object: `watchlistApi`
- Function: `watchlistApi.fetchWatchlist`
- Function: `watchlistApi.updateWatchlist`

## Tasks

<task>
  <read_first>
    - api/market.ts
    - api/_utils.ts
    - api/watchlist.ts
  </read_first>
  <action>
    Create a new proxy handler file `api/watchlist.ts`.
    It must route GET requests originating at `/api/watchlist` to Capital.com's `/api/v1/watchlists` endpoint to retrieve watchlists.
    It must route POST/PUT requests to update the watchlist (e.g., adding a symbol) to Capital.com's respective endpoint.
    Use `proxyRequest` from `api/_utils.ts` to ensure credential injection.
    Implement explicit error handling: if the Capital.com API returns an error (e.g., invalid symbol), the proxy must catch this and return a standard JSON error response with the specific status code and message.
  </action>
  <acceptance_criteria>
    - `api/watchlist.ts` exports a default async handler function.
    - `curl -X GET http://localhost:3000/api/watchlist` (or equivalent test) returns watchlist JSON.
    - Specific errors from Capital.com are forwarded with the correct HTTP status code rather than swallowed as 500s.
  </acceptance_criteria>
</task>
